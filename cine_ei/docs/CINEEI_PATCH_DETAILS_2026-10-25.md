# Cine EI 固化补丁：落点细节（V3）

- 机型：Sony ILCE-6700（A6700）
- 固件：2.00

基线链条：**原厂** → **FL23 基线**（原厂 + 112 B 转换窗口）→ **V3**（FL23 基线 + Cine EI 补丁）。

> 结构性识别不看哈希：原厂与 FL23 基线的程序头 `p_filesz` 都是 `0x4488EED`，V3 是 `0x4489230`。跨版本时先用这个判据确认自己在哪一档。

## 1. 规模

| 项 | 数值 |
|---|---:|
| 载体 `/usr/lib/appFw.so` | 89,027,992 B |
| 补丁段数 | 211 |
| 写入总字节 | 827 B |
| 相对 FL23 基线 | 209 段 / 823 B |
| `p_filesz` / `p_memsz` | `0x4488EED` → `0x4489230` |
| 新代码区（RX 尾段） | `0x4489190`–`0x4489230` |
| 入口 hook | `0x3304D0C`、`0x3300D44` |

## 2. 段的分组

| group | 段 | 字节 | 性质 |
|---|---:|---:|---|
| `static_island` | 114 | 652 | 新增 AArch64 代码主体 |
| `ui_source` | 63 | 63 | UI 列/槽/父项数据 |
| `native_code` | 17 | 65 | 原指令改写（跳进新增代码） |
| `support_source` | 7 | 7 | 支持状态源 |
| `compiled_default` | 4 | 4 | 编译默认值 |
| `rx_tail_island` | 2 | 30 | 尾段收尾 |
| `footer` | 2 | 2 | footer 字段 |

## 3. 为什么这版比 FL2/FL3 多一步

FL2/FL3 只改函数体、不动程序头，写完冷启动就生效。Cine EI 要往 RX 段**尾部追加代码**，因此：

1. 必须扩 `p_filesz` / `p_memsz`，否则新页不可执行；
2. 扩了程序头就必须先让**启动快照失效**：旧快照恢复的是旧段布局（`0x4488EED`），文件里的新头（`0x4489230`）不会被采用，跳到新代码就等于跳进全零页——这正是 v1 崩溃的原因；
3. 让快照失效的办法是把 WBI 分区头部 512 B 清零（分区 248,637,568 B，头 88 B，`sections=1314`，扇区 512 B），然后完整断电。

## 4. 写入序列

```
1) 只读预检 211 段（逐段比对 before，任一不符即中止）
2) 备份 WBI 512 B 头 → 清零 → 断电冷启动
3) remount /usr rw → 写 827 B → fsync → 回读 827 B → remount ro
4) O_DIRECT 复核真实内容
5) 断电冷启动 → 菜单确认 Cine EI
```

多段写入有顺序约束：**新增代码先写、跳转指令后写、程序头最后写**。反了会出现「跳到还没写好的代码」的中间态。

第 4 步不能用普通读取：普通读取命中页缓存，会看到「文件还是旧头」的假象，只有 `O_DIRECT` 才是闪存里的真实内容。

## 5. 验收标准

| 阶段 | 通过标准 |
|---|---|
| 预检 | `preflight=211/211` |
| 写入 | `written=827`、`verified=827` |
| 冷启动 | 快照状态 `idle`，加载头等于文件头 |
| 功能 | 菜单出现 Cine EI，且冷启动后仍启用（实机已确认） |
| 离线回归 | 两条 hook 正常返回；重定位/重载 420 例（118 保留、240 纠正） |

## 6. 回退阶梯

| 目的 | 手段 |
|---|---|
| V3 → FL23 基线 | 反向写 827 B（同一套预检 + 读回校验） |
| 回到旧快照启动 | 写回备份的 512 B WBI 头 |
| 全部复原 | 官方恢复包 |

三条都要**断电冷启动**才生效。

## 7. 已知的坑

1. 常规关机走 `mem`、不建快照；**BIS / 更新流程会走 `warm` 挂起并可能重建 WBI**，不要用那条路径关机；
2. 清头后不再有快照保护，回退依赖 USB 服务可用；USB 也不可用时只能走官方更新；
3. 固件升级会覆盖整份 AP，补丁表必须按新版本重做，不能沿用；
4. v1 的崩溃点就是尾段全零（执行到即取指故障），V2 仍有空洞，V3 才补齐；跨版本改用别的镜像时，先确认尾段没有空洞；
5. 每次写入前必须跑逐段预检，任何不符即中止，不要写半截。
