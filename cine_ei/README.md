# Cine EI / Cine EI Quick 的分层启用说明

以 A6700 2.00 上把 Cine EI / Cine EI Quick 接进现有拍摄链为例，说明这类改动如何分成
**菜单准入、支持层、HIGH 计算基准**三层，按什么顺序执行、每层如何验证与回滚。

本文只讲分层方法、顺序与判据；偏移、段数、hook 与程序头这些落点集中在一篇详情里
（[docs/CINEEI_PATCH_DETAILS_2026-10-25.md](docs/CINEEI_PATCH_DETAILS_2026-10-25.md)），
那一篇给数字、不含哈希。

---

## 1. 先判断：缺的是准入、支持，还是基准

这类目标通常不是“让相机跑一段新代码”，而是“处理链里已经具备 Cine EI 的能力，只是
A6700 的机型能力表、支持层或计算基准没有把它接进去”。判断顺序应当是：

1. 处理链里有没有这项能力（参数、模式、数据结构）；
2. 菜单能不能选（能力列、可用性、项目状态）；
3. 选进去之后，支持层和计算基准是否放行。

跳过前两步直接“改哪里”，会把“菜单没放行”误判成“能力缺失”，也容易在错误层面上反复
试错。

### 1.1 三条独立证据

| 证据 | 要回答的问题 | 典型反例 |
|---|---|---|
| 菜单准入 | Cine EI / Cine EI Quick 是否出现在 Log shooting，且不是灰色 | 只有内部枚举，菜单里没有词 |
| 支持层 | Base ISO / 曝光指数面板是否真的可用 | 菜单能选，但面板仍被禁止 |
| 计算基准 | HIGH 档的菜单范围与实际计算范围是否一致 | 菜单 640..10000，计算只接受 3200 以上 |

三条都齐，才叫“只差接入”。只有第一条时，通常只是“平台里编进了这个词”；只有前两条时，
HIGH 档仍会出现无效值、暗屏或黑屏。

### 1.2 同代平台不等于同机型

同一代平台上，图像引擎、菜单框架和参数表往往是共享的，差异主要落在**机型能力表**
（哪些能力允许被这台机器表达）与**产品配置数据**（默认值、可用性计数、菜单权限列）。
所以“代码都在、菜单没有”通常不是引擎缺失，而是准入层没放行；反过来，能力表里连这个
词都没有时，改菜单也不会生效。

## 2. 改动分成哪三层

| 层 | 改动对象 | 作用 | 不做什么 | 缺失时的现象 |
|---|---|---|---|---|
| 1. 菜单准入 | Log shooting 两个新增值的机型能力列、可用性字节、项目状态 | 让 Cine EI Quick / Cine EI 出现在菜单且可选 | 不选 Log/Base/EI，不调原厂 setter，不写 flash | 两个选项不出现，或出现但灰色不可选 |
| 2. 支持层 | 一组支持标志，以及成对的禁止计数/限制字节 | 解除 Base ISO / 曝光指数面板的“不支持”贡献 | 不选 Log/Base/EI 数值，不清掉其他模式条件的限制 | 菜单能选 Cine EI，但 Base/EI 面板仍被禁止，选 EI 变“—” |
| 3. HIGH 计算基准 | 两份 HIGH 基准副本 | 把 HIGH 计算从高 ISO 档（12800）对齐到 2500 档 | 不改当前 EI、Log/Base、菜单或显示 | HIGH 菜单有 640..10000，但 640/1600/2500 无效/暗/黑；Quick 阈值 1600 时出现空洞 |

三层性质不同：

- **菜单准入**是“能不能看见、能不能选”，只动准入判断；
- **支持层**是“选进去之后面板让不让用”，要区分“这次要解除的 unsupported 贡献”和
  “其他模式条件仍然保留的限制”；
- **HIGH 基准**是“计算时用哪一档作为锚点”，它不是当前 EI 下标，不能和 EI 数值混用。

### 2.1 一个常见误解

“菜单里能选”不等于“链路打通”。菜单准入只说明第一层过了；Base ISO / EI 面板可能仍被
支持层禁止，HIGH 档也可能仍按旧基准计算。三层必须分开验证。

---

## 3. 前置条件与顺序

### 3.1 前置条件

- 电量充足，准备备用电池；任何写入过程都不要碰线、不要断电；
- 准备**官方恢复包**（对应机型的官方固件更新文件），这是唯一的救生索；
- 先做**只读预检**：确认当前固件版本、目标参数区可读，记录改动前的状态；
- 先做**完整备份**：至少有一份改动前的原始数据副本，回滚不依赖相机上的残留状态。

### 3.2 执行顺序

顺序的原则是：**先做最外层、最容易验证的，再做最内层、后果最重的。**

```text
1. 菜单准入   —— 让两个选项可见、可选
2. 支持层     —— 让 Base ISO / 曝光指数面板真正可用
3. HIGH 基准  —— 让 HIGH 档的计算范围与菜单一致
```

每一层做完都要单独验证，确认无误后再进入下一层。不要三层连着做——一旦 EI 显示不对，
无法判断是菜单、支持层还是基准层。层与层之间留一个“回到已知良好状态”的检查点：任何
一层失败，先回滚该层，不要带着问题继续。

### 3.3 运行期与持久化

这三层在实验阶段都是**运行期改动**：只改当前开机内的状态，完整断电后回到原厂。真正在
菜单里选中 Cine EI / Cine EI Quick 时，走的是原厂 setter，Log 值会按原厂行为持久化到
flash——这不是菜单准入层写的，但回滚时要把它和运行期补丁分开处理。

显示布局、底栏文字、输入路由和 ISO/EI 耦合不在本文范围；它们各自是独立层，不能和这
三层混在一起验收。

---

## 4. 每层怎么验证

### 4.1 菜单准入

- Log shooting 菜单出现 Off / Flexible ISO / Cine EI Quick / Cine EI 四项；
- 两个新增项不是灰色，能进入选择；
- 选中后菜单状态正常，不重启、不报错。

只看到文字出现还不够：文字可能来自资源表，但选项仍被能力列或可用性计数拦住。必须以
“能否选中”为准。

### 4.2 支持层

- Base ISO 面板能打开，LOW/HIGH 能切换；
- 曝光指数面板能打开，选值后不显示“—”，不残留上一个值的格式片段；
- 实际控制生效，而不只是菜单文字变化。

如果菜单能进但面板仍被禁止，说明支持层的禁止计数/限制字节没有同步；如果面板能开但
选值无效，继续看 HIGH 基准层。

### 4.3 HIGH 基准

- HIGH 档菜单的 640 / 1600 / 2500 / 3200 等值可选；
- 选择后不出现“—”、暗屏或黑屏；
- Quick 阈值在 1600 附近时，1600 / 2000 / 2500 不再出现空洞；
- 宽容度格式（E 整数/小数）连续，不残留上一个 EI 的片段。

注意：黑屏不一定是基准层唯一原因。基准层解决的是“计算范围与菜单范围不一致”；如果
基准对齐后仍黑屏，要单独沿预览/增益/曝光模式查，不要继续在同一层反复写。

### 4.4 验收记录

| 项目 | 记录内容 |
|---|---|
| 版本 | 改动前的固件/参数区指纹 |
| 菜单 | 四项是否可见、两项是否可选 |
| 支持层 | Base/EI 面板是否可用，是否出现“—” |
| HIGH | 640/1600/2500/3200 与 Quick 阈值两侧 |
| 冷启动 | 完整断电后的状态 |
| 回滚 | 回滚后菜单/面板/基准是否复原 |

菜单文字、图标和功能要分开验收：功能生效但文字仍旧是常见现象，不代表改动失败。

## 5. 数据规模与结构

先按规模判断“这一步值不值得做”：

| 项 | 规模 | 说明 |
|---|---:|---|
| Log shooting 选项 | 4 项 | 新增 2 项：Cine EI Quick / Cine EI |
| 支持标志 | 约 7 个 | 对应 Base ISO、曝光指数等支持层 |
| 禁止计数/限制字节 | 约 114 对 | 成对处理，只解除确认的 unsupported 贡献 |
| HIGH 基准副本 | 2 份 | 两份必须一致，不能只改一份 |
| Base 档位 | 2 档 | LOW / HIGH |
| EI 阶梯 | 约 26 档 | 160 起，含高 ISO 档；菜单只开放其中一段 |

几个读法：

- 菜单准入的改动量很小，但它决定“有没有入口”；
- 支持层是成对计数，改一对可能影响多个模式条件，不能只改单边；
- HIGH 基准只有两份，但它决定 HIGH 档的整个有效范围；
- 数字只说明规模，不是补丁位置；不要从计数反推地址。

---

## 6. 位置为什么不写在这一篇里

菜单准入、支持层、HIGH 基准的改动量都不大，但它们分别位于启动关键路径、准入判断和
范围计算里。写错的后果可能是菜单异常、EI 显示错误，甚至主程序无法启动，所以位置必须
和版本前提绑在一起看：偏移、段数与写入字节数集中在
[落点细节](docs/CINEEI_PATCH_DETAILS_2026-10-25.md)，本文只讲方法与判据。

本文仍然不给：

- 补丁载荷与补丁表；
- 补丁模块的二进制；
- 原厂私有接口、备份/身份相关细节。

想确认自己找到的是不是那一处，用行为验证更可靠：固定一组输入（Log/Base/阈值/EI），
只有目标两项/目标范围发生变化，其余输入输出逐字节不变；再用冷启动确认结果来自预期层，
而不是运行期补丁。这是小时到天级的成本，不是分钟级。

## 7. 回滚

回滚顺序与写入顺序相反：

```text
1. HIGH 基准  —— 恢复两份基准
2. 支持层     —— 恢复支持标志与计数/限制字节
3. 菜单准入   —— 恢复能力列/可用性/项目状态
```

运行期改动在完整断电后自然消失；如果已经通过菜单选中 Cine EI 并持久化了 Log 值，要按
正常 UI 改回 Off / Flexible ISO，或使用官方恢复包，不能只依赖运行期 undo。

回滚后要完整断电冷启动，并重新核对菜单、Base/EI 面板和 HIGH 档，而不是只看某一项。

---

## 8. 已知的坑

1. **菜单可见 ≠ 可用**：能力列放行只解决入口，支持层可能仍禁止面板；
2. **支持层可用 ≠ HIGH 范围正确**：HIGH 基准仍可能是旧的高 ISO 档；
3. **HIGH 基准不是 EI 下标**：基准是计算锚点，不能和当前 EI 数值混用；
4. **Quick 阈值附近容易出空洞**：HIGH 基准不对时，1600/2000/2500 会随阈值移动；
5. **热重启不等于冷启动**：运行期补丁会掩盖真实状态，验证文件/持久化层前要先清掉；
6. **“—”和残留 E 是两种不同现象**：前者是无效哨兵，后者是格式参数没有刷新；
7. **黑屏要单独查**：基准对齐只保证范围一致，不保证预览/增益链一定正确；
8. **不同固件版本结论不同**：同一机型的不同版本，内部结构可能有差异，不要跨版本照搬；
9. **菜单文字/图标通常不能一起移植**：成像链、文字、图标是三套管线，功能与文字要分开验收；
10. **EVF / HDMI 可能不显示 EI**：布局与显示管线有作用范围，不能拿机背屏的结果推断所有输出。
