# FL2/FL3 移植：落点与验收细节

- 机型：Sony ILCE-6700（A6700）
- 固件：2.00
- 关系：本文是 [移植类改动的操作说明](README.md) 的落点补充；分层思路、执行顺序与回滚原则见那一篇
- 不含哈希：本文给偏移、窗口长度与写入字节数，不给任何文件或窗口哈希

> 偏移只在 2.00 上成立。官方固件更新会同时覆盖三层，升级后必须重新确认落点，不要跨版本照搬。

基线称呼：**原厂**（未改动）→ **FL23 基线**（原厂 + A 层 112 B）→ **候选**（FL23 基线 + B 层 33 窗口 + selector0）。

## 1. 三层落点总表

| 层 | 载体 | 载体大小 | 落点 | 改动量 | 生效条件 |
|---|---|---:|---|---:|---|
| A 应用层映射 | `/usr/lib/appFw.so` | 89,027,992 B | `0x34E5604`（所属函数入口 `0x34E55F0`） | 112 B | 冷启动 |
| B 成像处理数据 | `/cp/cpapp-b.bin` | 17,892,024 B | 33 个窗口，最小窗口在 `0x135F0A` | 9,536 B delta，实写 4,456 B | 完整断电 |
| C 色彩参数单元 | `02a40001` / `02a4000d` | 8,192 B / 28,672 B | 槽 23（FL2）/ 槽 25（FL3） | 71 B + 840 B = 911 B | 下次启动 |

写入顺序仍是 C → B → A（见 README §4）：先做最容易恢复的，最后做最难恢复的。

## 2. A 层：112 B 转换窗口

窗口只改一个函数体，不改其它任何结构：

| 输入 | 输出 CP mode |
|---|---|
| `selected=14`、`base=0` | 19（FL2） |
| `selected=15`、`base=0` | 20（FL3） |
| 其它 `selected` / `base` | 保持原值 |

- 离线验证：`converter`、`batch_call_site`、`incremental_handler` 三条路径各 525 组，只有上面两行变化，其余输入逐字节一致；带负对照（故意改错槽位能被检出）。
- 写入序列：`remount rw` → 写 112 B → `fsync` → 回读 112 B → `remount ro`；任一步不符即中止，不留半截状态。
- 该层**不改 ELF 程序头**（`p_filesz` 仍是 `0x4488EED`），不追加、不扩段，因此不涉及加载器布局，也不需要任何前置的启动侧操作。
- 冷启动判据：`libJit` 已清、完整断电、且没有跑过 RAM 补丁，三条同时成立时 `AP window = fl2` 且 nonce 匹配，才说明 fl2 来自文件而不是内存。
- 禁区：文件已是 patched 后，不要再跑 RAM 补丁或 `--probe`；`--probe` 会把 C6 送到 BW mode 5，制造「C6 黑白」的假象。

## 3. B 层：CP 模式数据

`/cp` 分区 24 MB、空闲约 3 MB，所以不传 17.9 MB 整文件，只发 delta 由机内原地写：

- delta 9,536 B，33 个窗口，实际写入 4,456 B；
- 每个窗口写前校验 before、写后回读 after，任一个不匹配就整批中止。

两份数据必须同时正确，否则现象会分叉：

| 数据 | 决定什么 | 只改一处的现象 |
|---|---|---|
| 42 项模式表 | 能不能切过去 | 菜单可选、成像不变 |
| 当前生效参数 | 切过去用什么 | 刚切有效、冷启动后回退 |

selector0 是候选相对 FL23 基线多出来的那一处实验补丁：

- 位置 `0x135F0A`，长度 2 B，`00 20 → 00 BF`（`movls r0,#0` → `NOP`）；
- 作用：把 movie-only gamma shim 的归一化 NOP 掉，使 still 参数不再被拉回 selector 0；
- 性质：非原厂行为；只影响这一处 shim，不改模式表；
- 验证：读回为 selector0，delta 逐窗口校验通过。

回滚在 B 层有强约束：当前是 selector0 时直接跑整文件回滚会 `before_mismatch`，必须先 revert 回 42 项候选，再回原厂。CP 与 AP 相互独立，可单独回滚。

## 4. C 层：色彩参数单元

| 单元 | 大小 | 写入 | 目标槽 |
|---|---:|---|---|
| `02a40001` | 8,192 B | 71 B | 23（FL2） |
| `02a4000d` | 28,672 B | 840 B | 25（FL3） |

- 每族 16 个风格槽；目标槽必须是空槽、且没有被其它参数引用，否则会出现「写了 A 槽、B 槽却还在用旧数据」。
- 每槽 8 项参数，本次验收值：对比度 0、高光 0、阴影 0、褪色 1、饱和度 0、锐度 4、范围 3、清晰度 1。
- 只写 911 B，但走设置侧落盘（`saveBackup(0x02a4)`）；冷启动后读回与备份记录一致才算成功，不靠「看起来像」。

## 5. 验收数字

六张同机位、同曝光、同参数的对照（ST / C5 / C6 各两张），1200 px、gain-matched 的平均绝对差：

| 对比 | MAD | 读法 |
|---|---:|---|
| ST a vs b | 1.27 | 噪声地板 |
| C5 a vs b | 1.39 | 噪声地板 |
| C6 a vs b | 1.41 | 噪声地板 |
| C5 vs C6 | 3.60–3.66 | 两条不同曲线 |
| ST vs C5 | 4.69 | 跨风格 |
| ST vs C6 | 3.13 | 跨风格 |

- 亮度均值：ST 80.1 / C5 93.6 / C6 94.9，暗部整体抬起（Fade=1 的胶片形态）。
- C5 vs C6 的形态：暗部 R `−3.8`、亮部 R `+5.0`，正负交叉 → 不是曝光差，是两条曲线。
- 验收参数：`0 0 0 1 0 4 3 1`（Base ST）。
- 保留项：这六张的 WB 是 Auto，R/B 有少量漂移；定妆对比应锁手动 WB 重拍。

## 6. 运行时改动与文件改动

- **COW / 内存补丁不构成固化**：它只改进程私有映射，`/usr` 是 `ext2 ro`，重启后内核按文件重新取页，一切回 BASE。它的价值是上机前验证行为，不是持久化。
- **单窗口可以在运行中原地写**：112 B 就是这么做的，实测通过。
- **改动面变大时换窗口**：几十上百处窗口建议在 `dmode=2`（infra + LIRO 起来、`appFw` 不加载）下写，此时文件没有被任何进程映射，不存在新旧页混读。
- **多窗口写入有顺序约束**：新增代码段先写、跳转指令后写、ELF 程序头最后写；顺序反了会出现「跳到还没写好的代码」的中间态。

## 7. 已知的坑（README §7 的补充）

1. 当前 CP 是 selector0 时直接跑整文件回滚会 `before_mismatch`，必须先 revert；
2. AP 文件已 patched 后跑 `--probe` 会得到「C6 黑白」的假象，不是真实成像；
3. 普通读取可能命中旧页缓存，看到「文件还是旧值」；要确认真实内容必须用 `O_DIRECT` 读；
4. 同一机型不同固件版本的偏移会变，本文数字不能跨版本套用。
