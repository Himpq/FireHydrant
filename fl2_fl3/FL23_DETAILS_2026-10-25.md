# FL2/FL3 移植：落点与验收细节

- 机型：Sony ILCE-6700（A6700）
- 固件：2.00

> 偏移只在 2.00 上成立。官方固件更新会同时覆盖三层，升级后必须重新确认落点，不要跨版本照搬。

基线称呼：**原厂**（未改动）→ **FL23 基线**（原厂 + A 层 112 B）→ **候选**（FL23 基线 + B 层 33 窗口 + selector0）。

## 1. 三层落点总表

| 层 | 载体 | 载体大小 | 落点 | 改动量 | 生效条件 |
|---|---|---:|---|---:|---|
| A 应用层映射 | `/usr/lib/appFw.so` | 89,027,992 B | `0x34E5604`（所属函数入口 `0x34E55F0`） | 112 B | 冷启动 |
| B 成像处理数据 | `/cp/cpapp-b.bin` | 17,892,024 B | 33 个窗口，最小窗口在 `0x135F0A` | 9,536 B delta，实写 4,456 B | 完整断电 |
| C 色彩参数单元 | `02a40001` / `02a4000d` | 8,192 B / 28,672 B | 槽 23（FL2）/ 槽 25（FL3） | 71 B + 840 B = 911 B | 下次启动 |

写入顺序仍是 C → B → A（见 README §4）：先做最容易恢复的，最后做最难恢复的。

## 2. A 层：112 B 转换窗口

窗口只改一个函数体，不改其它任何结构：

| 输入 | 输出 CP mode |
|---|---|
| `selected=14`、`base=0` | 19（FL2） |
| `selected=15`、`base=0` | 20（FL3） |
| 其它 `selected` / `base` | 走原有分发（差异见 2.1） |

### 2.1 窗口内指令

窗口按 4 字节对齐，原实现 28 条指令（`w1` = base，`w0` = selected）：

```asm
; rva 0x34E5604, 112 B
0x00  cmp   w1, #9
0x04  b.hi  #0x34E5674            ; base > 9 直接跳走
0x08  adrp  x0, #0x40B6000        ; 索引表
0x0c  add   x0, x0, #0x24
0x10  ldrb  w0, [x0, w1, uxtw]    ; w0 = idx[w1]
0x14  adr   x1, #0x34E5624        ; 跳转表基址
0x18  add   x0, x1, w0, sxtb #2   ; x0 = base + idx*4
0x1c  br    x0                    ; 计算跳转

0x20  mov   w0, #3
0x24  b     #0x34E55FC
0x28  mov   w0, #2
0x2c  b     #0x34E55FC
0x30  mov   w0, #1
0x34  b     #0x34E55FC
0x38  mov   w0, #0x10
0x3c  b     #0x34E55FC
0x40  mov   w0, #0xf
0x44  b     #0x34E55FC
0x48  mov   w0, #0x11
0x4c  b     #0x34E55FC
0x50  mov   w0, #0x12
0x54  b     #0x34E55FC
0x58  mov   w0, #5
0x5c  b     #0x34E55FC
0x60  mov   w0, #0xd
0x64  b     #0x34E55FC
0x68  strb  wzr, [x2]
0x6c  ret
```

改后：前 8 条保留，把计算跳转换成直接比较 selected，尾部换成一张 12 字节索引表 + NOP 填充：

```asm
; rva 0x34E5604, 112 B
0x00  cmp   w1, #9
0x04  b.hi  #0x34E5674
0x08  cbnz  w1, #0x34E5620        ; base != 0 走查表
0x0c  cmp   w0, #0xe              ; selected == 14 ?
0x10  b.eq  #0x34E5630
0x14  cmp   w0, #0xf              ; selected == 15 ?
0x18  b.eq  #0x34E5638
0x1c  adr   x0, #0x34E5640
0x20  ldrb  w0, [x0, w1, uxtw]
0x24  strb  w0, [x2]
0x28  ret

0x2c  mov   w0, #0x13             ; 19 = FL2
0x30  b     #0x34E55FC
0x34  mov   w0, #0x14             ; 20 = FL3
0x38  b     #0x34E55FC

0x3c  .byte 0x00,0x03,0x02,0x01,0x10,0x0f,0x11,0x12,0x05,0x0d,0x00,0x00
0x48  nop                          ; 10 条 nop 填充到 112 B
```

三点：

- 原来 `0x08`–`0x1c` 是「查索引 → 算跳转地址 → `br`」，改后 `0x08` 直接按 `base` 分流，`selected` 为 14/15 时落到 `mov w0,#0x13` / `#0x14`；
- `0x3c` 的 12 字节表只被 `base != 0` 的分支使用，`ldrb` 取一格、`strb` 写到 `[x2]`；
- 离线 525 组输入走的都是 `base = 0` 这条；`base != 0` 时改后行为与原实现不同（原为常量返回，现查表写入 `[x2]`），换机型或换调用点时先确认这一支不会被走到。

- 离线验证：`converter`、`batch_call_site`、`incremental_handler` 三条路径各 525 组，只有上面两行变化，其余输入逐字节一致；带负对照（故意改错槽位能被检出）。
- 写入序列：`remount rw` → 写 112 B → `fsync` → 回读 112 B → `remount ro`；任一步不符即中止，不留半截状态。
- 该层**不改 ELF 程序头**（`p_filesz` 仍是 `0x4488EED`），不追加、不扩段，因此不涉及加载器布局，也不需要任何前置的启动侧操作。
- 冷启动判据：`libJit` 已清、完整断电、且没有跑过 RAM 补丁，三条同时成立时 `AP window = fl2` 且 nonce 匹配，才说明 fl2 来自文件而不是内存。
- 禁区：文件已是 patched 后，不要再跑 RAM 补丁或 `--probe`；`--probe` 会把 C6 送到 BW mode 5，制造「C6 黑白」的假象。

## 3. B 层：CP 模式数据

`/cp` 分区 24 MB、空闲约 3 MB，所以不传 17.9 MB 整文件，只发 delta 由机内原地写：

- delta 9,536 B，33 个窗口，实际写入 4,456 B；
- 每个窗口写前校验 before、写后回读 after，任一个不匹配就整批中止。

两份数据必须同时正确，否则现象会分叉：

| 数据 | 决定什么 | 只改一处的现象 |
|---|---|---|
| 42 项模式表 | 能不能切过去 | 菜单可选、成像不变 |
| 当前生效参数 | 切过去用什么 | 刚切有效、冷启动后回退 |

selector0 是候选相对 FL23 基线多出来的那一处实验补丁：

- 位置 `0x135F0A`，长度 2 B，`00 20 → 00 BF`（`movls r0,#0` → `NOP`）；
- 作用：把 movie-only gamma shim 的归一化 NOP 掉，使 still 参数不再被拉回 selector 0；
- 性质：非原厂行为；只影响这一处 shim，不改模式表；
- 验证：读回为 selector0，delta 逐窗口校验通过。

回滚在 B 层有强约束：当前是 selector0 时直接跑整文件回滚会 `before_mismatch`，必须先 revert 回 42 项候选，再回原厂。CP 与 AP 相互独立，可单独回滚。

### 3.1 载荷：33 个窗口

`wbi/data/cp.delta`，9,536 B：

```
0x00   "A6700D01" | u32 version=1 | u32 count=33 | u64 原文件长度 | u64 载荷长度
0x60   count × 16 B：u64 偏移, u32 长度, u32 载荷内相对位置
之后   每窗两段：before 接 after
```

| 项 | 数值 |
|---|---:|
| 窗口数 | 33 |
| 写入字节 | 4,456 B（窗口长度合计） |
| 实际变化 | 2,080 B |
| 最大窗口 | `0x10D02B8`，3,872 B（1,682 B 变化） |

五个窗口是 4 B 指令：

| 偏移 | 改前 | 改后 |
|---|---|---|
| `0x317C70` | `msub w0, w22, w13, w28` | `msub w0, w22, w29, w28` |
| `0x318596` | `add w0, w22, #0x37c` | `add w0, w22, #0x77c` |
| `0x3185E4` | `add w0, w22, #0x37c` | `add w0, w22, #0x77c` |
| `0x3186C6` | `adr x0, #0x33451E` | `adr x0, #0x35451E` |
| `0x9B2DA6` | `add w0, w22, #0x37c` | `add w0, w22, #0x77c` |

其余 28 个是数据：`0x10D02B8`（3,872 B）和 `0x10D11D8`（168 B）两块表，剩下 26 处是 2–142 B 的零散字段。

selector0 那 2 B（`0x135F0A`）不在这个 delta 里，它打在候选之上。

写入工具在 [`wbi/host/cpdelta.py`](../wbi/host/cpdelta.py)，相机侧模块是 `wbi/native/cpdelta.c`。

## 4. C 层：色彩参数单元

| 单元 | 大小 | 写入 | 目标槽 |
|---|---:|---|---|
| `02a40001` | 8,192 B | 71 B | 23（FL2） |
| `02a4000d` | 28,672 B | 840 B | 25（FL3） |

- 每族 16 个风格槽；目标槽必须是空槽、且没有被其它参数引用，否则会出现「写了 A 槽、B 槽却还在用旧数据」。
- 每槽 8 项参数，本次验收值：对比度 0、高光 0、阴影 0、褪色 1、饱和度 0、锐度 4、范围 3、清晰度 1。
- 只写 911 B，但走设置侧落盘（`saveBackup(0x02a4)`）；冷启动后读回与备份记录一致才算成功，不靠「看起来像」。

## 5. 验收数字

六张同机位、同曝光、同参数的对照（ST / C5 / C6 各两张），1200 px、gain-matched 的平均绝对差：

| 对比 | MAD | 判读 |
|---|---:|---|
| ST a vs b | 1.27 | 噪声地板 |
| C5 a vs b | 1.39 | 噪声地板 |
| C6 a vs b | 1.41 | 噪声地板 |
| C5 vs C6 | 3.60–3.66 | 两条不同曲线 |
| ST vs C5 | 4.69 | 跨风格 |
| ST vs C6 | 3.13 | 跨风格 |

- 亮度均值：ST 80.1 / C5 93.6 / C6 94.9，暗部整体抬起（Fade=1 的胶片形态）。
- C5 vs C6 的形态：暗部 R `−3.8`、亮部 R `+5.0`，正负交叉 → 不是曝光差，是两条曲线。
- 验收参数：`0 0 0 1 0 4 3 1`（Base ST）。
- 保留项：这六张的 WB 是 Auto，R/B 有少量漂移；定妆对比应锁手动 WB 重拍。

## 6. 运行时改动与文件改动

- **COW / 内存补丁不构成固化**：它只改进程私有映射，`/usr` 是 `ext2 ro`，重启后内核按文件重新取页，一切回 BASE。它的价值是上机前验证行为，不是持久化。
- **单窗口可以在运行中原地写**：112 B 就是这么做的，实测通过。
- **改动面变大时换窗口**：几十上百处窗口建议在 `dmode=2`（infra + LIRO 起来、`appFw` 不加载）下写，此时文件没有被任何进程映射，不存在新旧页混读。
- **多窗口写入有顺序约束**：新增代码段先写、跳转指令后写、ELF 程序头最后写；顺序反了会出现「跳到还没写好的代码」的中间态。

## 7. 已知的坑（README §7 的补充）

1. 当前 CP 是 selector0 时直接跑整文件回滚会 `before_mismatch`，必须先 revert；
2. AP 文件已 patched 后跑 `--probe` 会得到「C6 黑白」的假象，不是真实成像；
3. 普通读取可能命中旧页缓存，看到「文件还是旧值」；要确认真实内容必须用 `O_DIRECT` 读；
4. 同一机型不同固件版本的偏移会变，不能跨版本套用。
