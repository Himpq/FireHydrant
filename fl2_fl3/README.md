# A6700 FL2/FL3 滤镜刷入

把 FL2 / FL3 两套 Creative Look 接到 A6700 的成像链上。落点、窗口长度与窗口内指令见 [FL2/FL3 落点与验收细节](FL23_DETAILS_2026-10-25.md)。

---

## 1. 能力、参数链、准入

目标是在旧机型上用上这个风格，不是往固件里塞一段新代码。判断从三个问题开始：

1. 固件里有没有这项能力（处理链、参数表、数据结构）；
2. 如果有，缺的是开关、映射关系，还是数据本身；
3. 确认缺失项之后，再决定要不要改文件。

### 1.1 三个检查点

| 检查点 | 问题 | 反例 |
|---|---|---|
| 符号与参数 | 处理链里有没有这个名字和参数 | 只有接口枚举，没有参数声明 |
| 参数链 | 读取、判定、写入、生效是否首尾相接 | 能写入但不广播、不重算 |
| 准入层 | 菜单权限、机型能力表、可用性计数是否放行 | 代码在，能力表里没有这一项 |

三项都过才算只差接入；只有第一项时，通常只是平台里编进了这个词。

### 1.2 引擎共享，差异在能力表

同代平台的图像引擎、色彩模块、菜单框架是共享的，差异在**机型能力表**（这台机器允许表达哪些能力）和**产品配置数据**（默认值、可用性计数、菜单权限列）。

所以「代码都在、菜单没有」通常是准入层没放行；能力表里连这个词都没有时，改菜单也不生效。

---

## 2. 三层结构

改动落在三个互相独立的位置，分开做、分开验证：

| 层 | 位置 | 作用 |
|---|---|---|
| A. 应用层映射 | 应用主程序 | 把菜单里的选择翻译成内部成像模式编号 |
| B. 成像处理数据 | 协处理器侧的模式数据文件 | 提供该模式实际使用的参数集合 |
| C. 色彩参数单元 | 独立的参数存储单元 | 存放该风格的色彩/伽马参数 |

三层性质不同：A 层是启动路径上的一小段代码；B 层是原地替换区间的数据文件；C 层只写设置数据，不碰固件镜像。

### 2.1 每层的约束

- **A 层**同时涉及转换逻辑（外部选择 → 内部模式编号）、能力表/权限列（选项是否可见）、可用性计数（多份引用共同决定可用性）。只改逻辑会「生效但菜单不出现」，只改准入层会「菜单出现但选不中」。
- **B 层**有两份数据：可选择的模式表（能不能切过去）和当前生效的模式数据（切过去用什么参数）。两份不一致会出现「显示已切换、成像没变」或「刚切有效、冷启动后回退」。
- **加载时机**：C 层下次启动生效，B 层必须完整断电冷启动，A 层在进程启动时加载。

---

## 3. 前置条件

- 电量充足，备一块电池；写入过程不断电、不碰线；
- 备份官方恢复包（对应机型的官方固件更新文件）；
- 只读预检：确认目标分区可写、当前固件版本符合预期；
- 完整备份：至少一份改动前的原始数据，回滚不依赖相机上的残留状态。

恢复包要先验证可用（版本匹配、介质可读、升级入口能进）；备份离线保存；每次写入前重新比对版本。

---

## 4. 写入顺序

按恢复难度排序，先做最容易回退的：

```
1. C 层：色彩参数单元    只写设置数据，可逆，风险最低
2. B 层：CP 模式数据     原地替换区间，有明确的前后状态判定
3. A 层：应用层映射      最后做，改动最小但后果最重
```

每层做完单独验证再进下一层。三层连着做时，成像不对就无法判断是哪一层。层与层之间留一个回到已知良好状态的检查点：任何一层失败先回滚该层。

---

## 5. 验证

**C 层**：写入前后各读一次单元，比对差异是否只在预期区间；写入后读回。

**B 层**：改动前记录文件指纹，改动后读回比对。这一层必须断电冷启动才生效，热重启读到的是旧内容，不要据此判断失败。

**A 层**：写入前比对整文件指纹是否为预期版本，写入后读回；再做冷启动验证——清掉运行时补丁、完整断电、重新开机，确认结果来自文件而不是内存补丁。

**成像**：固定机位和曝光拍一组对照，做量化比较。

### 5.1 验收记录

| 项目 | 记录内容 |
|---|---|
| 版本 | 改动前的整文件/整单元指纹 |
| 窗口 | 实际改动的区间与改动前后内容 |
| 读回 | 写入后立即读回的结果 |
| 冷启动 | 完整断电后的状态 |
| 功能 | 目标模式是否可选、是否实际生效 |
| 菜单 | 名称/图标是否变化（与功能分开记） |
| 回滚 | 是否演练过、回滚后指纹是否复原 |

成像对照要同镜头、同机位、同曝光与白平衡，覆盖高光、阴影、肤色与高饱和色；「观感更好」不是验收标准。

### 5.2 数据规模

| 层 | 载体 | 载体大小 | 实际改动量 | 生效条件 |
|---|---|---:|---:|---|
| A 应用层映射 | 应用主程序 | 89,027,992 B | 112 B 窗口（一条转换分支） | 冷启动 |
| B 成像处理数据 | CP 模式数据文件 | 17,892,024 B | 9,536 B delta / 33 个窗口，实际写入 4,456 B | 完整断电 |
| C 色彩参数单元 | 两个参数单元 | 8,192 B + 28,672 B | 71 B + 840 B = 911 B，落到两个空槽 | 下次启动 |

三点：

- A 层只改 112 B，但窗口前后都要做**整文件**指纹校验，不能只看窗口；
- B 层 33 个窗口，每个窗口写前校验 before、写后回读 after，一个不匹配就整批中止；
- C 层只动 911 B，但目标槽必须是空的且没有被其他参数引用，否则会出现「改了 A 槽、B 槽还在用旧数据」。

载体大小和改动量相差几个数量级，改动量小不代表风险小，风险由所在层决定。

### 5.3 验收标准

| 阶段 | 数量 | 通过标准 |
|---|---:|---|
| 离线分支验证 | 525 组 × 3 轮 | 只有目标分支变化，其余输入输出逐字节一致 |
| 独立实现交叉核对 | 19 项 | 双方地址/结果一致，不一致项要能解释 |
| 实机成像对照 | 6 张 | 固定机位、同曝光/白平衡，RAW+JPEG 各一组 |
| 冷启动 | ≥ 3 次 | 每次都能复现，且不依赖运行时补丁 |
| 回滚演练 | 每层 1 次 | 回滚后整文件/整单元指纹回到改动前 |

以下现象属于预期行为，不是故障：

- 菜单文字/图标不变：正常，成像链与资源管线是两套；
- B 层热重启不生效：正常，必须完整断电；
- 第一次冷启动后模式仍在，第二次启动消失：多半是两份模式数据不一致，不是写入失败。

### 5.4 结构规模

| 结构 | 规模 | 与本次移植的关系 |
|---|---:|---|
| 风格枚举 | 每族 16 槽（旧机型） | 目标风格只能落到空槽，槽位不能复用 |
| 内建风格 | 10 个 | 自定义槽的图标最多只能引用这 10 个之一 |
| look 记录 | 每条 160 B | 名称、引导语、图标槽、参数索引都在一条记录里 |
| CP 候选模式 | 42 项 | 实际只启用其中两项，其余保持原值 |
| 模式数据窗口 | 33 个 | 每个窗口独立校验，缺一个都不算完成 |
| 色彩参数 | 每槽 8 项 | 对比度、高光、阴影、褪色、饱和度、锐度、范围、清晰度 |

- **槽位是稀缺资源**：空槽被占用后，后续再移植别的风格就没有位置，规划时要一次留够；
- **参数整组生效**：8 项里改错一项成像就会偏，不能只对单项做「看起来差不多」的判断。

---

## 6. 回滚

- **C 层**：用备份的单元内容回写；
- **B 层**：用备份的数据文件整段回写，回滚后同样需要断电冷启动；
- **A 层**：用备份复回原始代码；若写入损坏导致主程序无法启动，只能靠官方恢复包。

回滚不应依赖被改动的那部分功能，这一点在设计阶段就要确认。回滚顺序与写入相反（先 A、再 B、后 C），前提是主程序还能启动；回滚后完整断电冷启动，重新计算整文件指纹确认与改动前一致。

---

## 7. 已知问题

1. **只切电源开关不够**：必须完整断电（拔电池），否则新数据不会加载，旧状态还留在运行期；
2. **B 层的改动热重启不生效**，容易误判为失败；
3. **运行时补丁会掩盖文件改动**：验证文件层前必须清掉所有内存补丁；
4. **界面不一定会变**：成像参数已经生效，菜单里的名字/图标可能仍是旧的；
5. **不同固件版本结论不同**：同一机型的不同版本，内部结构可能有差异，不要跨版本照搬；
6. **两份模式数据不一致**：会出现「能选但不生效」或「生效后回退」；
7. **AP 与 CP 各自独立回滚**：两边版本会漂移，必须分别记录状态；
8. **只比对首字节不够**：写入窗口要整段读回校验，局部位翻转可能不改变首字节。

---

## 8. 菜单文字与图标

成像、文字、图标是三条不同的管线：成像链是「模式编号 → 参数集合 → 色彩/伽马」；文字来自应用资源里的字符串表，旧机型可能没有目标字符串；图标走资源 id 与图库，图标槽位与成像模式不一一对应。

功能生效和菜单改名要分开验收。多数情况下正确做法是接受旧名字、只保证功能与参数正确；强行改文字/图标要动资源打包与引用表，收益低、风险高。

---

## 9. 风险

| 层 | 写坏后的后果 | 恢复手段 |
|---|---|---|
| C 层 色彩单元 | 成像异常，菜单可能报错 | 回写备份即可 |
| B 层 模式数据 | 成像异常或无法启动 | 回写备份；必要时官方恢复包 |
| A 层 应用层映射 | 主程序无法启动，运行时通道同时失效 | 仅官方恢复包 |
| D. 运行时补丁 | 本次开机内异常，断电即消失 | 断电重启；不要与文件改动混用 |

A 层放在最后，且必须在 B、C 两层验证通过、恢复包可用之后才动。运行时补丁只适合验证行为，不适合作为最终形态；验证文件层之前必须先清掉。

---

## 10. 误判

- **「界面没有变化」不等于「功能没有生效」**：界面与功能是两套机制，功能可能已生效而界面没有消费者；
- **「选项可选」不等于「链路打通」**：可选只说明准入判断通过，不代表下游的联动（参数重算、状态广播）已经发生；
- **「数据存在」不等于「数据正确」**：表项存在与表项内容符合预期是两件事；
- **「热重启后还在」不等于「已持久化」**：有些状态来自运行期缓存，只有完整断电才能区分。
